# ผลทดสอบ: การเลือกผลการเดินกราฟแบบใหม่ เทียบกับแบบเดิม (13 พ.ย. 2569)

Branch `feat/expansion-quota-and-paths` เปลี่ยน 2 อย่างใน `lightrag/retrieval.py`

1. **การเลือก 15 รายการลง context** เดิมหยิบ 15 โหนดแรกตามลำดับที่ BFS เดินถึง ใหม่แบ่งโควตาให้ทุก seed เท่ากัน
   ให้เส้นบทลงโทษ การอ้างข้ามมาตรา และข้อยกเว้นมาก่อน และให้เส้นโครงสร้าง (หมวด/ส่วน) ได้ที่เฉพาะเมื่อเหลือโควตา
2. **รูปแบบบรรทัด** เดิม `[hop1][DEFINES] sec_26: ...` ใหม่ `[hop1] def_biometric ←DEFINES— sec_26: ...`
   ซึ่งบอกโหนดต้นทางและทิศของเส้น

## วิธีทดสอบ

- คำถาม 8 ข้อ: 5 ข้อแต่งจากคำสั่งปรับทางปกครองของ สคส. ปีงบประมาณ 2568 ตามที่สื่อรายงาน, 2 ข้อจากประเด็นที่ประชาชนสับสน
  ซึ่งสื่อรายงานว่า PDPC Thailand เคยชี้แจง และ 1 ข้อเป็นคำถามลายนิ้วมือที่ใช้ใน Q&A log
- มาตราที่คาดหวังของแต่ละข้อ ผู้ทดสอบกำหนดเองจากตัวบทใน `data/pdpa_full_text_v2.md` ไม่ได้มาจากคำสั่งของ สคส.
  เพราะข่าวไม่ได้ระบุเลขมาตราของแต่ละคำสั่ง
- แต่ละคำถามเรียก LLM แตกคีย์เวิร์ด 1 ครั้ง แล้วใช้คีย์เวิร์ดชุดเดียวกันกับทั้งโค้ดเดิมและโค้ดใหม่
  seed และผลค้น chunk ของสองฝั่งจึงเหมือนกันทุกข้อ ต่างกันเฉพาะผลการเดินกราฟ
- รันใน container ที่ทำงานอยู่ (Qdrant 1.20.0, BGE-M3) โดยไม่ได้สร้าง index ใหม่และไม่ได้โหลด server ใหม่
- ข้อมูลดิบ: [2026-11-13-expansion-results.json](2026-11-13-expansion-results.json)

## สิ่งที่ดีขึ้น

- โหนดหมวดและส่วนไม่กินที่ใน context อีก (25 → 0 รายการ) ใน Q1 และ Q5 seed ตัวหนึ่งคือ `PDPA_2562` ซึ่งมีแต่เส้นโครงสร้าง
  แบบเดิมจึงเสีย 9 จาก 15 รายการไปกับรายชื่อหมวด
- โหนดบทลงโทษเข้ามาใน context (0 → 7 รายการ)
- มาตราที่คาดหวังเข้ามาเพิ่ม 2 ข้อ คือ ม.83 ใน Q2 และ ม.86 ใน Q5
- ทุกบรรทัดบอกต้นทางและทิศของเส้น

## สิ่งที่ไม่ดีขึ้นหรือแย่ลง

- **Q6 และ Q7 ล้มเหลวทั้งสองแบบ** ม.4 (ข้อยกเว้นกิจกรรมส่วนตัว) ไม่ถูกค้นเจอทั้งจาก profile และจาก chunk
  seed ที่ได้ไม่เกี่ยวกับคำถาม ปัญหาอยู่ที่ขั้นแตกคีย์เวิร์ดและขั้นค้น profile ซึ่ง branch นี้ไม่ได้แก้
- **ใน Q2 โหนดหน้าที่ถูกเบียดออก** แบบเดิมมี `obl_security` และ `obl_breach_notify` (แจ้งเหตุละเมิดภายใน 72 ชม.)
  ซึ่งตรงกับคำถาม แบบใหม่ให้เส้นอ้างข้ามมาตรามาก่อนเส้น `IMPOSES_OBLIGATION` สองโหนดนี้จึงไม่ได้ที่
- **โหนดบทลงโทษที่เข้ามาอาจไม่ใช่ของมาตราที่ถาม** กราฟมีโหนด Penalty เฉพาะของ ม.77, 79, 85, 86 และ 90
  ใน Q1 และ Q2 ซึ่งถามถึงผู้ควบคุมข้อมูล โหนดที่เข้ามาคือโทษของ ม.86 ซึ่งเป็นโทษของผู้ประมวลผล
  ส่วนโทษของผู้ควบคุมตาม ม.83 ไม่มีโหนด Penalty ในกราฟ

## ข้อจำกัดของการทดสอบ

- มีคำถามแค่ 8 ข้อ และแต่ละข้อใช้คีย์เวิร์ดชุดเดียว ทั้งที่ LLM แตกคีย์เวิร์ดได้ต่างกันในแต่ละครั้ง
- วัดเฉพาะว่ามาตราที่คาดหวังอยู่ใน context หรือไม่ ไม่ได้วัดคุณภาพคำตอบของ agent
  จึงยังไม่มีหลักฐานว่ารูปแบบบรรทัดใหม่ช่วยให้ LLM ให้เหตุผลได้ดีขึ้น
- กฎลำดับชนิดเส้นถูกปรับหนึ่งครั้งหลังเห็นผลรอบแรกของคำถามชุดนี้ (ให้เส้นโครงสร้างได้ที่เฉพาะเมื่อเหลือโควตา)
  ตัวเลขข้างบนจึงอาจดูดีกว่าที่จะได้กับคำถามชุดใหม่
