## อ่านผล

- **โค้ด main และ branch ได้ผลเท่ากัน คือ 1 จาก 6** การแก้ทั้งสามรอบไม่ช่วยกับคำถามชุดนี้ และ seed เหมือนกันทุกข้อ (ไม่มีข้อใดที่ `PDPA_2562` ติด 3 อันดับแรก)
- **ม.4 ไม่เข้า context เลยทั้ง 4 ข้อ** ทั้งที่เป็นหัวใจของคำตอบ สคส. ทุกข้อ สอดคล้องกับ Q6 และ Q7 ในรอบก่อนที่ขาด ม.4 เหมือนกัน
- **ต้นเหตุอยู่ที่ขั้นสกัด keywords** คำถามแบบชาวบ้านถามว่า "ผิดไหม" LLM จึงสกัดคำไปทางความยินยอม สิทธิของเจ้าของข้อมูล และบทลงโทษ ไม่มีคำว่า "ประโยชน์ส่วนตน" "กิจกรรมในครอบครัว" หรือ "ขอบเขตการใช้บังคับ" ซึ่งเป็นภาษาของ ม.4 การค้น profile และการค้นตัวบทจึงไปเจอ ม.19, 24, 27, 82, 83 แทน
- keywords มีเลขมาตราที่เดาเองจำนวนมาก R3 ไล่ "มาตรา ๔" ถึง "มาตรา ๔๑" ครบทุกเลข ซึ่งทำให้คำค้นฝั่ง low-level แทบไม่มีความหมาย
- กราฟมีข้อมูลที่ต้องใช้อยู่แล้ว: `sec_4` มีเส้นไป `exempt_personal`, `exempt_media` ฯลฯ ปัญหาคือการค้นไปไม่ถึง ไม่ใช่กราฟขาดข้อมูล

## ความหมายต่อระบบ

จากสถิติที่ สคส. เปิดเผย (แนวหน้า 21 ต.ค. 2569) ม.4 เป็นประเด็นร้องเรียนอันดับสอง (724 เรื่อง) รองจาก ม.27 (1,025 เรื่อง) คำถามแบบ "ทำแบบนี้ผิด PDPA ไหม" ที่คำตอบคือ "ไม่อยู่ในบังคับของกฎหมาย" จึงเป็นคำถามที่พบบ่อย และเป็นแบบที่ระบบนี้ตอบพลาดได้ง่ายที่สุด เพราะ context ที่ส่งกลับมีแต่หน้าที่และโทษ agent จึงมีแนวโน้มตอบว่าผิดและมีโทษ

## ข้อจำกัด

- 4 คำถาม และ 4 ใน 4 เกี่ยวกับ ม.4 เพราะคำตอบของ สคส. ที่สื่อรายงานพร้อมเลขมาตราที่หาได้เป็นเรื่องนี้เกือบทั้งหมด ผลจึงบอกได้เฉพาะจุดอ่อนเรื่อง ม.4 ไม่ใช่ภาพรวมของระบบ
- สกัด keywords ครั้งเดียวต่อคำถาม ผล LLM เปลี่ยนได้ในแต่ละรอบ
- มาตราที่ควรได้มาจากรายงานข่าว ไม่ได้มาจากหนังสือตอบข้อหารือฉบับเต็ม
- วัดเฉพาะสิ่งที่ server ส่งกลับ ไม่ได้ให้ agent ตอบจริงแล้วเทียบกับคำตอบของ สคส.
