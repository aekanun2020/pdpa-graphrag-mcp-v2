# ผลทดสอบรอบ 3 — ไม่ให้ PDPA_2562 เป็น seed (13 พ.ย. 2569)

ต่อจาก [รอบ 2](2026-11-13-expansion-round2.md) ข้อมูลดิบอยู่ที่ [2026-11-13-seed-filter-results.json](2026-11-13-seed-filter-results.json)

## สิ่งที่แก้

ใน `lightrag/retrieval.py` เพิ่ม `_NON_SEED_LABELS = {"Law"}` ตอนเลือก seed ถ้า node profile ที่ติดอันดับเป็นโหนดชนิด `Law` (มีโหนดเดียวคือ `PDPA_2562`) จะข้ามไป แล้วให้ node profile อันดับถัดไปขึ้นมาเป็น seed แทน โหนด `PDPA_2562` ยังถูกค้นเจอและแสดง VALUE ใน context ได้ตามปกติ แค่ไม่ใช้เป็นจุดเริ่มเดินกราฟ

## วิธีทดสอบ

ใช้ผลค้น profile และผลค้นตัวบทที่บันทึกไว้จากรอบ 2 (คำถาม 15 ข้อเดิม keywords เดิม) แล้วรันเฉพาะขั้นขยายกราฟสองแบบใน container ที่เปิดอยู่: ก่อนแก้ (โค้ด `35936c7`) กับหลังแก้ ไม่ได้เรียก LLM หรือ Qdrant ใหม่ ความต่างที่เห็นจึงมาจากการเลือก seed อย่างเดียว

## อ่านผล

- การแก้ทำงานตามที่ตั้งใจ: `PDPA_2562` ไม่เป็น seed อีก และโหนดหน้าที่/โทษในข้อมูลเชื่อมโยงเพิ่มขึ้น
- **จำนวนมาตราที่ควรได้ใน context ไม่ดีขึ้น** ชุดใหม่เท่าเดิม (9 จาก 12) ชุดเดิมลดลง 1 (Q2 เสีย ม.26)
- เหตุที่ Q2 เสีย ม.26: หลังรอบ 1 `PDPA_2562` แทบไม่ได้ที่ในข้อมูลเชื่อมโยงอยู่แล้ว (มีแต่เส้นโครงสร้าง) seed อีกสองตัวจึงแบ่ง 15 บรรทัดกันสองฝั่ง เมื่อ seed ที่สามเป็นโหนดจริง โควตาถูกแบ่งสาม บรรทัดของ seed เดิมจึงลดลง
- seed ที่ขึ้นมาแทนมักเป็นโหนดกว้างเหมือนกัน (`def_data_processor`, `def_data_controller`, `sec_80`) ปัญหา seed ไม่ตรงคำถามจึงยังอยู่ ต้นเหตุคือ keywords และการค้น profile ไม่ใช่ตัวกรองนี้
- ตัววัด "ในข้อมูลเชื่อมโยง" ไม่นับ seed เอง กรณี N6 ที่ ม.37 ขึ้นมาเป็น seed จึงดูเหมือนลดลงทั้งที่ ม.37 ยังอยู่ใน context

## ข้อจำกัด

- ใช้ keywords ชุดเดียวจากรอบ 2 ไม่ได้สกัดใหม่ และไม่มีคำถามใหม่ในรอบนี้
- มาตราที่ควรได้กำหนดโดยผู้ทดสอบจากตัวบท ไม่ได้วัดคุณภาพคำตอบของ agent
- ยังไม่ได้ build server ใหม่ container ที่รันอยู่ยังใช้โค้ด `main`
