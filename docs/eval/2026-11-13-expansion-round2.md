# ผลทดสอบรอบ 2 — ให้เส้นหน้าที่มาก่อน และคำถามชุดใหม่ (13 พ.ย. 2569)

## สิ่งที่แก้

ใน `lightrag/retrieval.py` ยกเส้น `IMPOSES_OBLIGATION` (มาตรา → หน้าที่) ขึ้นไปอยู่ลำดับ 0 เท่ากับ `PRESCRIBES_PENALTY` จากเดิมที่อยู่ลำดับ 2 (ค่าเริ่มต้น) เหตุผลคือรอบ 1 พบว่าโหนดหน้าที่ `obl_security` และ `obl_breach_notify` ถูกเส้นอ้างอิงข้ามมาตราเบียดออกในคำถาม Q2

| ลำดับ | ชนิดเส้น |
|---|---|
| 0 | `PRESCRIBES_PENALTY`, `IMPOSES_OBLIGATION` |
| 1 | `REFERENCES_SECTION`, `GRANTS_EXEMPTION`, `REFERENCES_EXEMPTION` |
| 2 | เส้นอื่นทั้งหมด (รวม `MUST_COMPLY_WITH`, `DEFINES`) |
| 3 | เส้นโครงสร้าง `CONTAINS_SECTION`, `HAS_CHAPTER`, `HAS_PART` (ใช้เติมช่องที่เหลือเท่านั้น) |

## วิธีทดสอบ

เหมือนรอบ 1: รันใน container ที่เปิดอยู่ ไม่ restart server เทียบโค้ด `main` (เก่า) กับโค้ด branch นี้ (ใหม่) โดยใช้ keywords ชุดเดียวกันทั้งสองฝั่ง

- **ชุดเดิม Q1–Q8** ใช้ keywords ที่บันทึกไว้จากรอบ 1 ชุดนี้เคยใช้ปรับกฎมาแล้วหนึ่งครั้ง จึงไม่นับเป็นหลักฐานอิสระ
- **ชุดใหม่ N1–N7** ตั้งจากข่าวและรายงานของ สคส. ที่ไม่ได้ใช้ในรอบ 1 เรียก LLM สกัด keywords ใหม่ และไม่ได้ใช้ปรับกฎใด ๆ

## อ่านผล

**ดีขึ้น**

- ข้อมูลเชื่อมโยงไม่มีบรรทัดโครงสร้างที่ไม่ช่วยตอบ (37→0 ในชุดใหม่) ช่องที่ได้คืนถูกใช้กับโหนดโทษและโหนดหน้าที่
- โหนดหน้าที่ที่หายไปใน Q2 กลับมา และโดยรวมเพิ่มขึ้นทั้งสองชุด

**ไม่เปลี่ยน**

- ในคำถามชุดใหม่ จำนวนมาตราที่ควรได้ใน context ทั้งก้อนเท่าเดิม (9 จาก 12) การแก้ส่วนขยายกราฟไม่ได้ทำให้ได้มาตราที่ถูกต้องมากขึ้น
- มาตราที่ขาด (N1 และ N7 ขาด ม.83, N2 ขาด ม.27, Q6 และ Q7 ขาด ม.4) ขาดทั้งฝั่งเก่าและใหม่ ต้นเหตุอยู่ก่อนขั้นขยายกราฟ: seed ที่ได้มักเป็นโหนดกว้าง (`PDPA_2562` เป็น seed ใน 4 จาก 7 คำถามชุดใหม่, `def_data_controller` 4 จาก 7) และ keywords จาก LLM มีเลขมาตราที่เดาเอง

**แย่ลง**

- เมื่อ seed เป็น `def_data_controller` โหนดหน้าที่ลดลง (N1 7→3, N3 7→4, Q4 7→3) เพราะเส้นจากนิยามไปหน้าที่คือ `MUST_COMPLY_WITH` ซึ่งยังอยู่ลำดับ 2 และต้องแบ่งโควตากับ seed อื่น
- โหนดโทษที่เข้ามาอาจเป็นโทษของมาตราอื่น (เช่น ม.85, ม.86 ของผู้ประมวลผล) เพราะกราฟมีโหนดโทษเฉพาะ ม.77, 79, 85, 86, 90 ไม่มีของ ม.82–84

## ข้อจำกัด

- ตัวอย่างเล็ก (7 คำถามใหม่) และสกัด keywords ครั้งเดียวต่อคำถาม ผล LLM เปลี่ยนได้ในแต่ละรอบ
- วัดเฉพาะสิ่งที่ server ส่งกลับ ไม่ได้วัดคุณภาพคำตอบของ agent
- ยังไม่ได้ build server ใหม่ container ที่รันอยู่ยังใช้โค้ด `main`
