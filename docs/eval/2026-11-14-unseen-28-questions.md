# ผลทดสอบรอบ 13 — harness กับ lab8 บน 28 คำถามที่ยังไม่เคยใช้ (14 พ.ย. 2569)

ต่อจาก [รอบ 12](2026-11-14-learner-reproduction.md) รอบนี้เทียบ agent สองตัวบนคำถาม 28 ข้อในคลังที่ยังไม่เคยใช้กับ agent ตัวใด ทั้งสองตัวใช้โมเดลเดียวกัน เรียก server ตัวเดียวกัน และคำตอบถูกตรวจปนกันภายใต้รหัสสุ่ม ผลดิบอยู่ที่ `eval/unseen28/`

**สรุป: ทั้งสองระบบสรุปถูกเกือบทุกข้อ harness แม่นกว่าในระดับข้อความ** ข้อสรุปถูก 26 จาก 27 สำหรับ harness และ 25 จาก 27 สำหรับ lab8 ในระดับข้อความ harness ถูก 260 จาก 265 (98%) ไม่มีข้อความผิด และทุกข้อความมีตัวบทรองรับ ส่วน lab8 ถูก 411 จาก 439 (94%) มีข้อความผิด 5 ข้อความใน 5 คำตอบ และมี 13 ข้อความที่ไม่มีตัวบทรองรับ ตัวเลขนี้ใกล้กับที่วัดได้บน 24 ข้อชุดก่อน (harness 98% กับ lab8 94%) แต่ละข้อรันครั้งเดียวต่อระบบ

## วิธีทดสอบ

**server:** สร้างใหม่ก่อนทดสอบจาก `main` ที่ commit `c1bd5ec` ด้วย `docker compose build --no-cache` และ `docker compose up -d` ทั้ง `mcp-pdpa-rag` และ `qdrant` (Qdrant 1.20.0) หลังสร้างใหม่ตรวจแล้วว่าไฟล์ใน container ตรงกับ `main` ทั้ง 6 ไฟล์ แพ็กเกจ Python ตรงกับก่อนสร้างใหม่ 116 จาก 116 และเครื่องมือ 4 ตัวที่ไม่ใช้ LLM ให้ผลตรงกับก่อนสร้างใหม่ 289 จาก 289 ครั้ง server สกัด keywords ด้วย `gpt-oss-120b`

**agent สองตัว** ใช้ `deepseek/deepseek-v4.1-flash` ผ่าน OpenRouter ทั้งคู่ และเรียก server ตัวเดียวกันที่ port 8100

### รูปแบบของข้อความที่ถูกบางส่วน

- **เงื่อนไขของมาตรา ๗๙:** เขียนโทษอาญาเป็นของการฝ่าฝืนมาตรา ๒๗ ทั่วไป โดยไม่บอกว่าต้องเป็นข้อมูลตามมาตรา ๒๖ พบทั้งสองระบบ และเป็นเหตุของข้อสรุปถูกบางส่วนในข้อ N2 ของทั้งสองระบบ
- **อ้างวรรคผิดในมาตราที่ถูก:** โดยเฉพาะข้อตกลงระหว่างผู้ควบคุมกับผู้ประมวลผลตามมาตรา ๔๐ (วรรคสาม) ที่ถูกเขียนเป็นวรรคสองหรือวรรคท้าย พบหลายคำตอบของ lab8
- **อ้างมาตราเกินกว่าที่ตัวบทเขียน** ในหัวข้อคำแนะนำ เช่น มาตรา ๑๙ วรรคสี่ มาตรา ๓๗ (๒) และมาตรา ๓๙ (๗)

### ข้อสรุปถูกบางส่วน 3 คำตอบ

- **N2 ทั้งสองระบบ:** ระบุการฝ่าฝืนมาตรา ๒๗ และโทษปรับตามมาตรา ๘๓ ถูก แต่พูดถึงโทษอาญาตามมาตรา ๗๙ โดยไม่บอกเงื่อนไขเรื่องข้อมูลตามมาตรา ๒๖
- **N5 ของ lab8:** ระบุความรับผิดตามมาตรา ๗๗ และถ้อยคำ "ไม่เกินสองเท่า" ของมาตรา ๗๘ ถูก แต่อธิบายเพดานผิดตามตารางข้างบน

## ข้อจำกัด

- แต่ละข้อรันครั้งเดียวต่อระบบ ตัวเลขรายข้อจึงมีความแกว่งของโมเดลปนอยู่
- ผู้ตรวจเป็น subagent ของ Claude ไม่ใช่นักกฎหมาย และตรวจกับตัวบทของพระราชบัญญัติเท่านั้น
- การปิดชื่อระบบไม่สมบูรณ์: คำตอบของ harness ขึ้นต้นด้วยรูปแบบตายตัว ("**สรุปคำตอบ:**") ส่วน lab8 เขียนอิสระ ผู้ตรวจจึงอาจแยกได้ว่าคำตอบมาจากคนละระบบ แม้ไม่รู้ว่าระบบใดเป็นระบบใด
- จำนวนข้อความต่อคำตอบต่างกันมาก (lab8 เฉลี่ย 16.3 harness เฉลี่ย 9.8) คำตอบที่ยาวกว่ามีโอกาสพลาดมากกว่า ร้อยละจึงเทียบได้โดยประมาณ และจำนวนข้อความผิดควรอ่านคู่กับความยาว
- ผู้ตรวจนับข้อความในหัวข้อคำแนะนำไม่เท่ากัน บางตัวนับเมื่อข้อความนั้นอ้างสิ่งที่พระราชบัญญัติกำหนด บางตัวข้าม ข้อความผิดของ lab8 อย่างน้อย 1 ข้อความ (P6) อยู่ในหัวข้อคำแนะนำ
- 28 ข้อนี้ไม่เคยใช้กับ agent แต่บางข้อเคยใช้ในรอบวัดการค้น (รอบ 1 ถึง 10) ก่อนที่ prompt ของ harness จะถูกเขียน จึงไม่ใช่คำถามที่ไม่เคยเห็นโดยสิ้นเชิงสำหรับ harness ส่วน lab8 ไม่ได้ถูกปรับตามคำถามชุดใด
- harness รอบนี้รันบนเครื่องโดยตรงด้วย Python ของเครื่อง ไม่ใช่ใน container เหมือนรอบ 11
- ทดสอบบน Mac ชิป ARM เครื่องเดียว บน server ของผู้สอนที่สร้างใหม่จาก `main` ไม่ได้รันบนชุดที่สร้างจาก zip แยกต่างหาก

## เหตุที่เกิดกับ server ระหว่างเตรียมการ

- ระหว่าง build image ใหม่ container `mcp-pdpa-rag` ตัวเดิม restart เอง 1 ครั้ง เวลาตรงกับขั้นที่ build โหลดโมเดล BGE-M3 ขณะที่ server ใช้หน่วยความจำอยู่ราว 3.6 GB จาก 7.65 GB ไม่มี log ยืนยันสาเหตุโดยตรง
- หลังจากนั้น container ทั้งสองถูกสร้างใหม่ และไม่มีการ restart ระหว่างการทดสอบ ไม่มีการใช้ `docker compose down`
