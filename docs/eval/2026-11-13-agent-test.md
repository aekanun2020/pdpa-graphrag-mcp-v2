## วิธีทดสอบ

## รอบที่รันไม่จบ

ทั้ง 3 รอบเป็นของ `main` และล้มแบบเดียวกัน: agent สั่ง `search_pdpa` เป็นครั้งแรก แล้ว server ไม่ตอบภายใน 120 วินาที harness จึงหยุดด้วย `TimeoutError` หลังเรียกโมเดลไป 2 ครั้ง ยังไม่มีหลักฐานใดถูกเก็บ

### เวลาหายไปที่ขั้นใด (จาก log ของ server)

### ข้อสรุปเรื่อง timeout

- เวลาที่หายไปอยู่ในขั้นสกัด keywords ไม่ใช่ที่ Qdrant หรือการเดินกราฟ
- การแย่ง CPU ระหว่าง server สองตัวไม่ใช่เหตุจำเป็น เพราะรันตัวเดียวก็ยังมีครั้งที่ใช้ 100.8 วินาที
- timeout ไม่ได้ผูกกับคำถาม 3 ข้อนั้น ข้อเดิมรันซ้ำแล้วจบ จึงเป็นเรื่องของโอกาสที่การสกัด keywords ครั้งหนึ่งจะช้าเกิน 120 วินาที ซึ่ง prompt ของ `main` มีโอกาสนี้ (10 จาก 59 ครั้งเกิน 60 วินาทีเมื่อรวมสองรอบ) ส่วน prompt ของ branch ไม่พบเลยใน 71 ครั้ง
- ยังไม่ได้พิสูจน์ว่าทำไม prompt ของ `main` จึงช้าเป็นบางครั้ง จำนวน keywords ที่ไม่จำกัดเป็นคำอธิบายที่เข้ากันได้แต่อธิบายได้ไม่หมด และไม่ได้แยกเวลาของ LLM ออกจากเวลา embedding

## ทำไมคำตอบไม่ต่างกันทั้งที่ context ต่างกัน

รอบ 4 ถึง 9 พบว่า `main` ไม่ส่ง ม.4 มาใน context ของ `search_pdpa` ครั้งเดียว (0 จาก 9) แต่รอบนี้ agent บน `main` อ้าง ม.4 ได้ทุกข้อที่รันจบ (6 จาก 6) เพราะ agent ไม่ได้ค้นครั้งเดียว:

- ค้นซ้ำด้วยคำของตัวเอง เช่น R3 บน `main` ค้นครั้งที่สองด้วยคำว่า "ข้อยกเว้น กิจกรรมส่วนตัว ครัวเรือน" แล้วอ่าน ม.4
- อ่านตัวบทด้วย `get_section_text` และตามเส้นเชื่อมด้วย `get_related_sections` ซึ่งไม่ผ่าน `retrieval.py` สองรุ่นจึงตอบเหมือนกัน
- prompt ของขั้นสืบค้นสั่งให้ตรวจว่ากฎหมายใช้บังคับกับกรณีนั้นหรือไม่ก่อนสรุป

เนื้อหาคำตอบของกลุ่ม ม.4 ที่รันจบทั้งสองรุ่นไปทางเดียวกัน เช่น H1 (แอบบันทึกเสียงเก็บไว้ฟังเอง) ทั้งสองรุ่นตอบว่าไม่ผิดตาม ม.4 (1) และ H2 (ศาลเผยแพร่คำพิพากษา) ทั้งสองรุ่นตอบว่าไม่ต้องขอความยินยอมตาม ม.4 (5) พร้อมตั้งข้อสังเกตเดียวกันว่าตัวบทไม่ได้เขียนคำว่าเผยแพร่คำพิพากษาไว้ตรง ๆ

## ข้อจำกัด

- รันข้อละครั้งต่อรุ่น โมเดลไม่คงที่แม้ตั้ง seed (รอบนำร่องให้ contract ต่างกันจากข้อมูลเข้าเดียวกัน) ผลต่างระดับ 1 ถึง 2 มาตราจึงแยกจากความแปรปรวนของโมเดลไม่ได้
- ยอดรวมการเรียกเครื่องมือของ branch สูงกว่าเพราะ `main` มี 3 รอบที่หยุดก่อนได้เรียก เมื่อเทียบเฉพาะ 21 ข้อที่จบทั้งสองรุ่น ภาระงานของ agent ใกล้กัน: เรียกเครื่องมือ `main` 215 ครั้ง branch 208 ครั้ง, เรียกโมเดล 146 กับ 148 ครั้ง, ค่า deepseek 0.181 กับ 0.188 USD ต่างกันที่ branch เรียก `search_pdpa` มากกว่า (57 กับ 48 ครั้ง)
- ชุด PDPA ของ harness เขียนขึ้นในวันเดียวกับที่ทดสอบ ผ่านการทดสอบแบบไม่เรียกโมเดล 20 ข้อและรอบนำร่อง 4 รอบ ยังไม่เคยถูกวัดกับชุดคำถามอื่น
- ชุด PDPA ของ harness ไม่ได้ถูกปรับให้เข้ากับคำถามรายข้อ: prompt และ hook ไม่มีเลขมาตรา รหัสคำถาม หรือคำจากโจทย์ และแก้ครั้งเดียวระหว่างนำร่องกับชุดจริง (เพิ่มบรรทัดให้ตอบเป็นภาษาไทย) แต่ถูกเขียนโดยรู้ประเภทของคำถามและจุดอ่อนจากรอบ 4 ถึง 10: prompt ของขั้นสืบค้นสั่งให้ตรวจว่ากฎหมายใช้บังคับกับกรณีนั้นหรือไม่ รวมถึงมาตราที่ทำให้กิจกรรมอยู่นอกกฎหมาย, อธิบายวิธีหาบทกำหนดโทษ และ hook บังคับให้ข้อเรียกร้องเรื่องโทษผูกกับบทกำหนดโทษ คำถามนำร่อง 2 ข้อ (R3, P3) อยู่ในชุด 24 ข้อด้วย คะแนนสัมบูรณ์ของรอบนี้จึงน่าจะสูงกว่าที่ agent ทั่วไปจะได้ และข้อสังเกตว่า agent อ้าง ม.4 ได้บน `main` ส่วนหนึ่งมาจากคำสั่งใน prompt การเทียบ `main` กับ branch ยังใช้ได้เพราะใช้ harness ชุดเดียวกันทุกตัวอักษร
- agent ตัวอื่นที่ค้นครั้งเดียวแล้วตอบ หรือไม่เรียก `get_section_text` จะพึ่ง context ของ `search_pdpa` มากกว่านี้ ผลรอบ 4 ถึง 10 ยังใช้ได้กับ agent แบบนั้น
